## 二、为什么原件不入库（这是纪律，不是偷懒）

| 原因 | 说明 |
|---|---|
| **1. 体积** | 原件 **112.87 MB**。GitHub 对 **>100 MB 单文件直接拒绝 push**；本项目红线更严：**单文件 > 10 MB 即不入库** |
| **2. 历史不可逆** | Git 历史不可变。一旦提交，即使之后 `git rm`，**旧 blob 永久留在对象库**，谁来 clone 都要下这份体积 —— **这正是旧仓 702.6 MB 的根因** |
| **3. 评审不会下载它** | 112 MB 的 `.pptx` 对评审是负担；**可读的压缩 PDF** 才是有效形态 |

**正确处置**：

```
PPT 原件（.pptx，112.87 MB）  → 本地 + 网盘留存，❌ 不入库
PPT 压缩版（.pdf，≤6 MB）      → 入库 或 放 Release 附件（二选一，建议 Release）
```

压缩建议：在演示软件里「另存为 PDF + 压缩图片」，19 页控制在 **≤6 MB**。
本仓库预留了放行写法（`.gitignore` 里 `*.pdf` 默认忽略，需入库时用 `!` 显式放行单个文件）。
