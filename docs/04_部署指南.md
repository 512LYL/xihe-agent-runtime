# 部署指南

> 目标：从零把「多通道 AI Agent 运行底座」跑起来。
> **原则：本仓库不含任何真实密钥、网关 IP、账号或本机绝对路径**；
> 所有环境相关的值一律通过环境变量注入（见 [`.env.example`](../.env.example)）。

---

## 一、环境要求

| 项 | 要求 | 备注 |
|---|---|---|
| 操作系统 | Windows 11（生产实测环境） | Linux 亦可，路径与环境变量改用对应写法 |
| Python | 3.12+ | 桥接器与看护层 |
| Node.js | 24.x（OpenClaw 要求 ≥ 22.19.0） | 仅核心调度需要 |
| Ollama | 已拉取本地模型 `qwen3.5:4b`（2.55 GB） | 通道② 兜底 |
| 国产 GPU（可选） | 沐曦 C500，MACA 3.5.3.20，vLLM 0.17.0 | 通道③ 实证通道 |

## 二、安装

```powershell
git clone <你的仓库地址> xihe-agent-runtime
cd xihe-agent-runtime
pip install -r requirements.txt
Copy-Item .env.example .env      # 然后编辑 .env 填入你自己的值
```

## 三、双账号权限隔离（安全设计）

系统采用**两个独立账号**运行不同组件：

| 账号 | 角色 | 运行什么 |
|---|---|---|
| 主账号（管理员） | 日常使用与维护 | **Ollama**（便于管理维护） |
| 受限账号（标准用户） | AI 运行环境 | **OpenClaw Gateway / 应龙桥接器 / 看护层** |

**设计目的**：把 AI 限制在**标准用户**账号中运行，使其**无法接触管理员权限**，
防止 AI 在无人监督时越权操作系统。两账号通过**本机回环地址**通信，服务**仅对本机开放**。

> ⚠️ 注意：Ollama 若装在主账号下，启动时需切到该账号操作（`Win+L` 切换），再切回受限账号。

## 四、端口分配（现役）

| 端口 | 服务 | 协议 | 说明 |
|---|---|---|---|
| 11434 | Ollama | HTTP | 本地模型推理 API（通道②） |
| 11443 | 应龙桥接器 | HTTP/SSE | OpenAI 兼容；Gateway 唯一模型入口 |
| 18000 | 通道③ 隧道 | TCP 转发 | 本机 `18000` → C500 实例 `8000`（vLLM） |
| 18791 | OpenClaw Gateway | HTTP/WS | 控制面板 + API |
| 8080 | QQ 桥（接管发送） | HTTP | 主动推送端点 `/send` |
| 3002 / 6099 | NapCat | WS / HTTP | QQ 机器人实例 / WebUI |

> 历史端口（已随版本升级迁走，**出现即为过期配置**）：`11440 / 11441 / 11442 / 18789 / 18790`。
> 全部端口可用环境变量覆盖：`XIHE_BRIDGE_PORT` / `OPENCLAW_GATEWAY_PORT` / `C500_LOCAL_PORT` / `OLLAMA_PORT`。

## 五、分通道启动

### 5.1 通道②｜本地 Ollama（先跑通这条，零成本）

```powershell
ollama list                        # 确认 qwen3.5:4b 已就绪
python src\bridge\yinglo_bridge.py # 启动应龙桥接器
python src\health\health_system_check.py   # 一键体检
```

### 5.2 通道①｜云端 API（多源韧性对照项）

```powershell
# .env 中填 MUXI_API_KEY / MUXI_PACKAGE_ID
Copy-Item src\config\openclaw.template.json "$env:OPENCLAW_STATE_DIR\openclaw.json"
python src\entry\launch_gateway.py --port 18791 --verbose
```

> 配置模板的形态要点：**Gateway 里没有任何外部云端 provider**，只有 `muxi`（实际指向本机 Bridge）
> 与 `bridge` 两个后端 —— 所有请求经 Bridge 路由，由 Bridge 按网络状态决定透传云端还是走本地。

### 5.3 通道③｜沐曦 C500 自部署 32B

```powershell
# 1) 编辑 scripts\tunnel_c500.bat，把 <C500_GATEWAY_HOST> / <C500_SSH_PORT> / <C500_SSH_USER> 换成你的值
#    （真实值只放本地 .env 或本机副本，绝不入库）
scripts\tunnel_c500.bat

# 2) 连通性自检（会打印实测延迟，可与基线对照）
python scripts\check_c500.py

# 3) 实例内启动 vLLM
vllm serve /models/Qwen2.5-32B-AWQ --served-model-name xihe-32b --port 8000 `
     --gpu-memory-utilization 0.85 --max-model-len 8192 --trust-remote-code
#    需要工具调用时追加： --enable-auto-tool-choice --tool-call-parser hermes
```

**基线对照**（MetaX C500 32G 切片 / MACA 3.5.3.20 / vLLM 0.17.0）：

| 指标 | 基线 |
|---|---|
| `GET /v1/models` | 1.07 s |
| `POST /v1/chat/completions`（中文） | 1.91 s |
| 3 轮平均 | 1.17 s |
| 点名通道③ 端到端 | 4.16 s |
| 复杂任务自动路由 | 19.68 s |

### 5.4 看护层

```powershell
python src\health\watchdog.py --once             # 一轮探活
python src\health\watchdog.py                    # 常驻（120 s 轮询，单例守卫自动生效）
python src\health\gateway_unstick.py --once --json
```

### 5.5 重复实例与卡死排查

```powershell

dir $env:XIHE_RUNTIME_ROOT\*.pid
```

## 六、关键技术决策（部署时必须知道）

| # | 决策 | 原因 |
|---|---|---|
| 1 | 桥接器使用 **ThreadingHTTPServer** | 主请求转发云端耗时 60–134 s，单线程会阻塞 health check 与并发请求。改用多线程后 **5 个并发 health check 全部 0–56 ms 返回** |
| 2 | launcher 启动前**清除 `SAFE_DELETE*` / `CODEBUDDY*` 环境变量** | 见 [03_九条踩坑根因.md](03_九条踩坑根因.md) 坑 6（`orphan-self-pid` 锁误判），清除后 **0 次复发** |
| 3 | 工具数从 **45 优化到 27** | 移除 MCP filesystem（14 个工具）与 lossless-claw（4 个工具）后，云端多工具响应时间从 **40–55 s 降至 20–30 s（降幅约 30%）** |
| 4 | 本地模型工具**剥离后注入 system prompt**（最多 4 个） | GGUF 模型不支持原生 `tools` 参数 |
| 5 | 会话写锁用**原子单例守卫** | 应用层「检查后创建」有竞态，曾导致双实例并存 16.4 h |
| 6 | **不上 Git LFS** | 瘦身后入库最大件是 MB 级 PDF/截图；上 LFS 只增加 clone 门槛 |

## 七、升级注意事项

1. **浏览器缓存**：升级 OpenClaw 后首次访问需**强制刷新**（`Ctrl+Shift+R`），否则会报 `protocol mismatch`（前后端 WebSocket 协议版本不一致）。
2. **配置有两个来源**：`openclaw.json` 与 `models.json` 都可能定义模型，改模型要**两处都看**。
3. **`contextWindow` 不能乱设**：声明值**虚高**会导致网关预算公式算出偏大的预算，进而触发引擎侧 400 超限（已实际发生：声明 40960 vs vLLM 实际 32768）。
4. **改完必须重启 Gateway** 才生效。

## 八、公开前 / 推送前自检（必做）

```powershell
python scripts\scan_secrets.py --strict     # 敏感信息 + 大文件全量扫描（红线闸门）
pwsh scripts\push-all.ps1 -DryRun           # 远端/提交/体积体检，不推送
```

- ❌ 大二进制（视频 / PPT 原件 / 大 PDF / 模型权重 / 大日志）一律不入库；
- ❌ 单文件 > 10 MB 即不入库（平台红线为 > 100 MB 拒收，本项目更严）；
- ✅ 只有 `*.example` 形态的**占位符**可以入库。
